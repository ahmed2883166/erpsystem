# إدارة قاعدة بيانات Admrail ERP v2 على Windows

## قبل البدء

- هذه الأداة مخصصة لجهاز الخادم الذي عليه PostgreSQL 16 وAdmrail.
- أوقف تشغيل Admrail مؤقتًا قبل تغيير اسم القاعدة أو حذف قاعدة قديمة.
- شغّل الملف Admrail-Database-Manager.cmd من مجلد البرنامج الرئيسي.
- ستحتاج كلمة مرور مسؤول PostgreSQL باسم postgres. لا تحفظها داخل ملف أو ترسلها لأحد.
- يجب أن يكون النسخ الاحتياطي المشفر مهيأ مسبقًا، وأن يكون لديك ملف الاسترداد وكلمة مروره في مكان آمن.

## قائمة الأداة

| الاختيار | معناه |
|---|---|
| 1 | فحص اتصال PostgreSQL واسم القاعدة وحجمها وعدد الاتصالات |
| 2 | تحديث الجداول والترحيلات مع الاحتفاظ ببيانات الشركات |
| 3 | إنشاء قاعدة جديدة، ويمكن تحويل البرنامج إليها بعد أخذ نسخة من القاعدة الحالية |
| 4 | تغيير اسم القاعدة الحالية وتحديث backend/.env تلقائيًا |
| 5 | حذف قاعدة قديمة غير نشطة فقط، بعد نسخة احتياطية مشفرة وتأكيد اسمها حرفيًا |
| 6 | إنشاء كلمة مرور جديدة لمستخدم PostgreSQL الذي يتصل به البرنامج وتحديث backend/.env |
| 7 | تغيير كلمة مرور مستخدم Admrail من خلال Django |
| 8 | استعادة نسخة احتياطية إلى قاعدة منفصلة دون الكتابة فوق القاعدة النشطة |\n| 9 | عرض كل قواعد البيانات وأحجامها وتحديد القاعدة النشطة بعلامة واضحة |\n| 10 | اختيار قاعدة قديمة، أخذ نسخة مشفرة منها، إنشاء قاعدة جديدة وتجهيزها، ثم الاختيار صراحةً إن كنت تريد حذف القديمة |

## الفرق بين تحديث القاعدة وإعادة إنشائها

**تحديث القاعدة الحالية:** ينفذ migrate ثم يجهز العملات والبيانات المرجعية. لا يحذف قيودًا أو فواتير أو أرصدة.

**إنشاء قاعدة جديدة:** ينشئ قاعدة مستقلة. لا يحذف القاعدة القديمة. إذا اخترت تحويل البرنامج إليها، تؤخذ نسخة مشفرة من القاعدة الحالية أولًا، ثم يتغير إعداد الاتصال وتُجهز الجداول. عند فشل الترحيل يرجع إعداد الاتصال إلى القاعدة السابقة.

**استبدال قاعدة بقاعدة جديدة (الاختيار 10):** يعرض أسماء القواعد ويضع علامة على القاعدة النشطة. تختار القاعدة القديمة واسمًا جديدًا؛ تحفظ الأداة نسخة مشفرة وتتحقق منها، ثم تنشئ القاعدة الجديدة وتحوّل اتصال التطبيق إليها وتنفذ الترحيلات والعملات والفحص. لا تحذف القاعدة القديمة إلا بعد نجاح تجهيز الجديدة، وبعد تأكيدين صريحين: كتابة «نعم» ثم كتابة اسم القاعدة حرفيًا. إذا فشل تجهيز الجديدة، يرجع الاتصال إلى القاعدة السابقة وتظل القاعدة المختارة محفوظة. إذا ألغيت الحذف، تظل القاعدة القديمة كما هي. لا يحذف دور PostgreSQL (Role) تلقائيًا.\n\n**عرض القواعد (الاختيار 9):** يعرض اسم كل قاعدة وحجمها، ويحدد القاعدة التي يتصل بها Admrail حاليًا.

## كلمات المرور

هناك ثلاث كلمات مرور مختلفة:

1. **مستخدم Admrail:** كلمة دخول الموظف أو مدير النظام. الاختيار 7 يغيرها.
2. **مستخدم PostgreSQL الخاص بالتطبيق:** غالبًا admrail_app. الاختيار 6 ينشئ كلمة مرور قوية جديدة ويحدث ملف الاتصال تلقائيًا.
3. **مسؤول PostgreSQL postgres:** كلمة إدارية مستقلة. الأداة تطلبها عند بدء التشغيل ولا تخزنها. إذا نسيتها، لا يمكن للاختيار 6 تجاوزها؛ يلزم استرداد إداري على Windows وفق إجراء PostgreSQL آمن. لا تحذف القاعدة ولا تعِد تثبيت PostgreSQL لمحاولة استعادة هذه الكلمة.

## قواعد السلامة

- لا تحذف القاعدة القديمة قبل نجاح إنشاء القاعدة الجديدة والتحقق من اتصال التطبيق بها.\n- الاختيار 10 ينقل اتصال التطبيق إلى القاعدة الجديدة بعد نجاح الترحيلات؛ لا يحذف القاعدة القديمة إلا بعد تأكيدك النهائي.
- لا تحذف backend/.env؛ يحتوي إعداد الاتصال ومفتاح Django.
- لا تشارك backend/.env أو ملفات النسخ الاحتياطي أو ملف استرداد التشفير.
- لا تعتبر إنشاء ملف النسخة كافيًا؛ يجب الاحتفاظ بملف النسخة المشفر وملف استرداد التشفير وكلمة مروره.
- الاستعادة تتم إلى قاعدة جديدة مستقلة. لا تغيّر الاتصال إليها إلا بعد اختبارها.
- لا تستخدم أداة التثبيت الأول Setup-Admrail.cmd لتحديث تثبيت قائم.

## ملاحظة التوافق

الأداة تعمل مع PostgreSQL 16 على Windows وتستخدم ملفات المشروع الحالية backend/.env وبيئة Python المرفقة وأوامر النسخ الاحتياطي والتشفير الموجودة. لا تستخدمها قبل اكتمال التثبيت الأول وتهيئة النسخ الاحتياطي المشفر.
