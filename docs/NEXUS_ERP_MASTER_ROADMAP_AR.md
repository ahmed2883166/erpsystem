# خارطة الطريق الرئيسية لتحويل NEXUS ERP إلى ERP مؤسسي متعدد الأنشطة

**النطاق المستهدف:** شركات متوسطة وكبيرة، متعددة الشركات والفروع والأنشطة.  
**اللغة الأساسية للواجهة والتوثيق:** العربية، مع المصطلحات الإنجليزية القياسية.  
**حالة الوثيقة:** مرجع تخطيطي تنفيذي؛ لا تعني أن الوظائف المذكورة منفذة أو معتمدة إنتاجيًا.  
**فرع العمل:** `feature/company-setup-currency-tax-activity`

## 1. الرؤية والقرارات المعمارية

NEXUS ERP منصة واحدة ذات نواة مشتركة ووحدات أعمال قابلة للتفعيل حسب نشاط الشركة. لا يُنشأ برنامج منفصل لكل نشاط، ولا تُكرر قواعد المحاسبة والمستخدمين والأطراف والمستندات بين الوحدات.

### المبادئ الملزمة

1. **مصدر موحد للحقيقة:** بيانات الشركة والأطراف والأصناف والحسابات والمستندات لها تعريف مركزي.
2. **محرك ترحيل مركزي:** كل مستند مالي يرحّل عبر `accounting_core.post_journal` أو واجهة مركزية معتمدة لاحقًا؛ لا تكتب الوحدات قيودًا مباشرة في جداول اليومية.
3. **دورة مستندية كاملة:** إنشاء، حفظ كمسودة، إرسال، اعتماد/رفض، ترحيل، إلغاء أو عكس وفق قواعد المستند.
4. **فصل المهام:** منشئ المستند لا يعتمد عمليته الحساسة منفردًا عند اشتراط الرقابة ذلك.
5. **تعدد الأبعاد:** الشركة، الفرع، الإدارة، مركز التكلفة، المشروع، النشاط، المخزن، العملة والفترة.
6. **سلامة التاريخ:** المستند المرحّل لا يُحذف أو يُعدل بصمت؛ التصحيح بعكس أو إشعار مرتبط بالمصدر.
7. **ترقيات آمنة:** migrations إضافية قابلة لإعادة التشغيل، مع نسخة احتياطية واختبار ترقية/استعادة، وعدم تعديل أرصدة العميل تلقائيًا.
8. **توطين منفصل:** قواعد الضرائب والفوترة الإلكترونية والعملات والتقارير النظامية تُحمّل بحسب دولة الشركة، ولا تخلط قواعد مصر والسعودية.
9. **قياس قبل التحسين:** كل تحسين أداء له benchmark قابل للتكرار، ولا تستخدم بيانات الشركات الحقيقية في اختبارات التطوير.
10. **لا اعتماد إنتاجي دون قبول:** نجاح اختبارات الوحدة وحده لا يساوي قبول دورة تشغيل فعلية.

## 2. جرد أولي للوحدات الموجودة

هذا الجرد مستند إلى ملفات المصدر والوثائق الموجودة في المستودع عند إعداد الخطة. حالة "موجود/أولي" لا تعني اكتمال الوظيفة؛ يجب تنفيذ مراجعة routes والجداول والاختبارات والواجهات قبل إغلاق كل بند.

| المجال | ملفات/مكونات ظاهرة بالمستودع | التقييم الأولي |
|---|---|---|
| التطبيق والنواة المحاسبية | `app.py`, `accounting_core.py`, `database.py`, `app_paths.py` | موجودة؛ تحتاج مراجعة شاملة للتكامل والصلاحيات والمعاملات |
| دليل الحسابات وملفات الأنشطة | `chart_templates.py`, `activity_profiles.py` | موجودة؛ يلزم اختبار نشاط مختلط وتغيير النشاط بعد بدء القيود |
| المبيعات والعملاء | `sales.py`, `quotations.py`, `receivables.py` | جزئية؛ دورة عرض/طلب/تسليم/فاتورة/مرتجع واعتماد تحتاج استكمالًا |
| المشتريات والموردون | `purchases.py` | جزئية؛ الاستلام الجزئي ومطابقة السطور والأسعار والاعتمادات تحتاج استكمالًا |
| المخزون والمواقع | `stock.py` | موجودة كأساس؛ الجرد المعتمد وحجز المخزون والفحص ومواقع التخزين تحتاج مراجعة |
| الخزينة والبنوك | `banking.py` | موجودة جزئيًا؛ التسوية البنكية ودورة الشيكات والمدفوعات تحتاج قبولًا |
| القوائم والتخطيط المالي | `income_statement.py`, `financial_planning.py`, `management_dashboard.py` | موجودة أوليًا؛ يلزم تدقيق IAS 7 والنسب والتحليلات وربط الحسابات |
| الأبعاد التحليلية | `analytic_dimensions.py` | موجودة؛ يلزم ربطها بكل المستندات والتقارير |
| العملات | `currency_center.py` | موجودة؛ يلزم اختبار فروق العملة وإعادة التقييم والتسويات |
| الضرائب | `tax_center.py` | موجودة؛ التوطين النظامي لكل دولة غير مكتمل |
| الأصول الثابتة | `fixed_assets.py` | موجودة؛ دورة الأصول الكاملة والقبول المحاسبي تحتاج مراجعة |
| الموظفون والرواتب | `workforce.py`, `payroll_compliance.py` | موجودة؛ يلزم اختبار الدورة الكاملة والامتثال حسب الدولة |
| التقارير والتصدير | `report_exports.py`, `party_reports.py` | موجودة؛ يجب التحقق من اكتمال البيانات مع pagination والفلاتر |
| النسخ والاستعادة | `backup_restore.py`, `backup_scheduler.py` | موجودة؛ اختبار استعادة عملي على بيئة Windows ما زال مطلوبًا |
| الأمان والتراخيص | `security_controls.py`, `licensing.py`, `license_server.py` | موجودة؛ لا تعتبر مراجعة أمنية أو نشر ترخيص إنتاجي مكتملًا |

### وظائف لم يظهر لها مكوّن مستقل في جرد الملفات الأولي

هذه ليست حكمًا نهائيًا بعدم وجود أي جزء منها؛ تُراجع routes والجداول قبل بدء التنفيذ:

- CRM متكامل لإدارة العملاء المحتملين والفرص والأنشطة.
- إدارة المشروعات والعقود والمستخلصات ومقاولي الباطن.
- التصنيع وBOM وMRP وأوامر الإنتاج (مؤجلة عمدًا).
- الصيانة الوقائية وأوامر الصيانة.
- إدارة الأسطول والرحلات والشحنات.
- نقاط البيع POS وإدارة الفروع/المطاعم والفنادق.
- بوابة API موثقة للتكاملات الخارجية.
- مركز مهام وإشعارات واعتمادات عام قابل لإعادة الاستخدام.
- تعدد الشركات مع معاملات Intercompany وتسوياتها.

## 3. خريطة الوظائف المستهدفة

### أ. النواة المؤسسية المشتركة — Enterprise Core

- الشركات القانونية، الفروع، الإدارات، المواقع ومراكز التكلفة.
- المستخدمون والأدوار والصلاحيات الدقيقة على مستوى الوحدة والعملية والبيانات.
- فصل الصلاحيات بين العرض والإنشاء والتعديل والاعتماد والترحيل والعكس.
- محرك حالات المستندات وسير الموافقات متعدد المستويات.
- ترقيم المستندات حسب الشركة والفرع والسنة ونوع المستند.
- محرك ترحيل مركزي وقواعد حسابات وضرائب حسب الشركة والنشاط.
- سجل تدقيق غير قابل للتعديل من واجهة المستخدم، مع before/after وسبب العملية.
- إدارة المرفقات والتعليقات والمهام والإشعارات.
- إدارة الفترات والسنوات وإقفالها وفحص جاهزية الإقفال.
- سجل أخطاء وتشخيص ومراقبة أداء.

### ب. المالية والمحاسبة — Finance

- الأستاذ العام GL، العملاء AR، الموردون AP.
- قيود متكررة، استحقاقات، دفعات مقدمة، تسويات، عكس وربط المستندات.
- الخزينة والبنوك والشيكات والتسويات البنكية.
- العملات وإعادة تقييم الأرصدة وفروق العملة.
- VAT والضرائب والاستقطاعات والزكاة/ضريبة الدخل حسب الدولة.
- الأصول والإهلاك والاستبعاد.
- الموازنات ومراكز التكلفة والربحية حسب الفرع والنشاط والمشروع.
- القوائم المالية والتدفقات النقدية والنسب مع إيضاح منهجية الحساب.

### ج. المشتريات والإمداد — Procure to Pay

- طلب احتياج داخلي PR.
- طلب عروض RFQ ومقارنة الموردين.
- أمر شراء PO واعتماده.
- استلام كلي/جزئي وفحص جودة وقبول/رفض.
- GRNI ومطابقة ثلاثية على مستوى السطر والكمية والسعر والضريبة.
- فاتورة المورد، إشعار الدائن، المرتجع، الدفعة المقدمة والسداد.
- سجل أسعار الموردين وتقييم الالتزام بالتوريد.

### د. المبيعات والتحصيل — Order to Cash

- CRM والعملاء والفرص والأنشطة.
- عروض الأسعار وقوائم الأسعار والخصومات المعتمدة.
- أوامر البيع وحدود الائتمان والحجز.
- تسليم كلي/جزئي وإثبات تكلفة المبيعات.
- الفواتير والمرتجعات والإشعارات الدائنة.
- تحصيل موزع على فواتير محددة، وتسويات وأعمار الديون.
- تحليل ربحية العميل والصنف ومندوب البيع.

### هـ. المخازن — Warehouse Management

- عدة شركات وفروع ومخازن ومناطق ورفوف ومواقع Bin.
- وحدات قياس وتحويلات مضبوطة.
- باركود ومسح واستلام وصرف وتحويل وحجز.
- مخزون تحت الفحص ومرفوض وتالف.
- Lots/Serials والصلاحية عند الحاجة.
- جرد دوري ومفاجئ وموافقة فروق الجرد.
- FIFO أو المتوسط وفق سياسة الشركة، مع سجل تكلفة قابل للتتبع.
- تقييم مخزون وربط دائم مع الأستاذ العام.

### و. وحدات متخصصة حسب النشاط

| النشاط | وظائفه المتخصصة |
|---|---|
| التجارة والتوزيع | تسعير، عروض، خصومات، مخازن، مندوبون، مرتجعات |
| الصناعة | BOM، MRP، أوامر إنتاج، WIP، هالك، انحراف تكلفة |
| المقاولات | مشروعات، عقود، مستخلصات، ضمانات، مقاولو باطن، تكلفة مشروع |
| الخدمات | عقود خدمة، ساعات عمل، مراحل إنجاز، إيراد مستحق |
| اللوجستيات | شحنات، رحلات، ناقلون، عمولات، تكلفة رحلة |
| الطبي | خدمات، موافقات تأمين، مطالبات، تسويات شركات التأمين |
| المطاعم والفنادق | POS، وصفات، استهلاك، تكلفة وجبة، إشغال وخدمات |

يجب أن يسمح النظام للشركة بتفعيل أكثر من نشاط في الوقت نفسه. ملف النشاط يضيف إعدادات وقواعد ووحدات، ولا يستبدل دليل حسابات مستخدم أو يغيّر أرصدة سابقة.

## 4. مراحل التنفيذ وترتيب الأولويات

| المرحلة | نطاق التنفيذ | مخرجات الإغلاق |
|---|---|---|
| 0 — التدقيق | جرد routes والجداول والصلاحيات والاختبارات والواجهات | مصفوفة موجود/جزئي/ناقص مع روابط الملفات والاختبارات |
| 1 — Enterprise Core | شركات وفروع وأبعاد، موافقات، ترقيم، محرك مستندات، صلاحيات | دورة اعتماد وترحيل قابلة لإعادة الاستخدام ومختبرة |
| 2 — Procure to Pay | PR/RFQ/PO/استلام/فحص/فاتورة/سداد | سيناريو شراء كامل مع استلام وفاتورة جزئية ومطابقة |
| 3 — Order to Cash | CRM/عرض/طلب/حجز/تسليم/فاتورة/تحصيل | سيناريو بيع كامل مع تسليم جزئي ومرتجع |
| 4 — Finance Advanced | بنوك، تسويات، موازنات، مراكز تكلفة، تقارير وضريبة | مطابقة الأستاذ والمساعد والتقارير والقوائم |
| 5 — Enterprise Operations | HR، أصول، مشروعات، صيانة، نقل | سيناريو تشغيلي مستقل لكل وحدة مع أثره المالي |
| 6 — Industry Packs | ملفات أنشطة متعددة وتخصيص الوحدات | شركة تجريبية متعددة الأنشطة دون تضارب في الحسابات |
| 7 — BI & Integrations | API، استيراد، تنبيهات، تقارير تنفيذية | توثيق API واختبارات صلاحيات وتكامل |
| 8 — Production Readiness | أمن، أداء، استعادة، ترقية، نشر | اجتياز بوابة الإصدار الرسمي |

التصنيع وBOM لا يبدأ قبل استقرار المخزون والتكلفة والمحاسبة، حفاظًا على قرار نطاق الإصدار الأول السابق.

## 5. معايير القبول الإلزامية لكل وحدة

1. سيناريو نجاح كامل من إنشاء المستند حتى أثره النهائي.
2. سيناريو رفض/إلغاء/عكس، مع الاحتفاظ بالأثر التاريخي.
3. اختبار صلاحيات مستخدمين بأدوار مختلفة.
4. اختبار منع التكرار وإعادة إرسال الطلب.
5. اختبار التزامن والمعاملة الذرية عند ترحيل المستند.
6. مطابقة كمية المخزون وقيمته مع الحركات وطبقات التكلفة.
7. مطابقة الأستاذ العام مع أرصدة العملاء والموردين والبنوك والمخزون.
8. التحقق من الضرائب والعملات والتواريخ والفترات المغلقة.
9. اختبار pagination والتصدير والفلاتر على كل النتائج لا الصفحة الحالية فقط.
10. اختبار migrations على نسخة قاعدة قديمة ونسخة فارغة، مع rollback أو إجراء استعادة موثق.
11. اختبارات آلية ناجحة ونتيجة CI مرتبطة بالـcommit نفسه.
12. اختبار قبول واجهة المستخدم على Windows ببيانات تجريبية.

## 6. بوابة اعتماد الإنتاج

لا يصدر NEXUS كمنتج إنتاجي لمجرد اكتمال الشاشات. يلزم:

- مراجعة محاسبية مستقلة للقيود وسياسات التقييم والتقارير.
- مراجعة أمنية للصلاحيات والجلسات وCSRF والأسرار والملفات المرفقة.
- اختبار استعادة نسخة احتياطية على بيئة منفصلة.
- اختبار أحمال واقعية وعدد مستخدمين متزامنين محدد.
- مراقبة الأخطاء والسجلات وخطة دعم وترقية.
- توثيق إجراءات التشغيل والترحيل من النسخة السابقة.
- اعتماد مالك المنتج قبل الدمج إلى `main` أو نشر الإصدار.

## 7. أول تسليم مطلوب الآن

**تسليم المرحلة 0 — التدقيق التفصيلي**، ويشمل ملفًا أو تقريرًا يربط كل وظيفة بـ:
- route أو endpoint.
- ملف Python المسؤول.
- الجداول ذات الصلة.
- القالب/الشاشة.
- الصلاحية المطلوبة.
- الاختبارات الحالية.
- النواقص ومخاطر التكامل.
- معيار القبول المقترح.

لا تُنشأ وحدات تشغيلية جديدة قبل اكتمال هذا الجرد، لتجنب التكرار أو إضعاف مسارات قائمة.
