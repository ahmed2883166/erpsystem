# توافق PostgreSQL — الشريحة 15: تسلسل الأكواد الذري

## النطاق

تم تجهيز `code_sequences.py` للعمل مع SQLite وPostgreSQL دون تغيير صيغة الأكواد الظاهرة للمستخدم:

- SQLite يحتفظ باستخدام `BEGIN IMMEDIATE` عندما لا توجد معاملة قائمة، حفاظًا على سلوك الحجز الحالي.
- PostgreSQL يستخدم `SELECT ... FOR UPDATE` لقفل سجل التسلسل أثناء الحجز.
- عند أول حجز لمفتاح تسلسل، يستخدم PostgreSQL `INSERT ... ON CONFLICT DO NOTHING` ثم يقرأ سجل الفائز بالقفل؛ وهذا يعالج سباق أول حجز بين جلستين.
- الاستعلامات ذات معاملات `?` تمر عبر `execute_compat`.
- أسماء الجدول والعمود والبادئة والعرض تتحقق قبل بناء SQL.
- لا تنفذ الدالة `COMMIT`؛ يظل الحجز وإدراج العميل/المورد/المستند ضمن معاملة المستدعي.

## اختبارات الحماية المضافة

- اختبارات SQLite السابقة تستمر في التحقق من استكمال الترقيم من الأكواد التاريخية، واستقلال المفاتيح، وإمكانية التراجع.
- اختبارات PostgreSQL تستخدم Schema معزولًا باسم فريد، وتتحقق من استمرار الترقيم والتراجع.
- اختبار تزامن بجلسَتين مستقلتين يحاولان أول حجز للمفتاح نفسه، ويتحقق من الحصول على رقمين مختلفين ومتتاليين.
- الاختبارات لا تفتح قاعدة بيانات الشركة ولا تستخدم مجلد `data/`.

## شروط التشغيل

- اتصال PostgreSQL يجب أن يكون `autocommit=False`؛ الحجز الذري لا يعمل على مستوى المعاملة مع autocommit.
- جدول `document_sequences` جزء من مخطط التشغيل ويجب إنشاؤه ضمن تهيئة/ترحيلات قاعدة البيانات قبل الاعتماد الإنتاجي. تحتفظ الدالة بإنشاء احتياطي `IF NOT EXISTS` للتوافق مع مسار SQLite الحالي.
- هذه الشريحة لا تحول اتصال Flask إلى PostgreSQL ولا تعني اكتمال ترحيل بقية مولدات المستندات.

## الحالة
