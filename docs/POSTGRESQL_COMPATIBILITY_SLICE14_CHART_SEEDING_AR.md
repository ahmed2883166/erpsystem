# توافق PostgreSQL — الشريحة 14: تهيئة دليل الحسابات

## النطاق
تم تحويل عمليات تهيئة دليل الحسابات في `chart_templates.py` إلى طبقة تنفيذ محايدة لقاعدة البيانات:

- فحص أعمدة الحسابات باستخدام `table_columns`.
- تنفيذ الاستعلامات ذات معاملات `?` عبر `execute_compat`.
- إنشاء الحسابات وإرجاع المعرف الناتج عبر `insert_one_returning_id` بدل الاعتماد على `cursor.lastrowid`.
- يشمل ذلك إنشاء الدليل الأولي، وإضافة الحسابات المشتركة، وإضافة حسابات النشاط، وإنشاء مجموعة الالتزامات طويلة الأجل عند الحاجة أثناء توحيد ضريبة القيمة المضافة.

## ضمانات المحافظة على البيانات
- لا تتغير أكواد الحسابات الحالية أو معرفاتها بسبب هذا التعديل.
- لا يتم تحديث قيود اليومية أو أرصدتها أو روابطها.
- الإضافات تظل تكرارية آمنة: الحساب الموجود لا يعاد إنشاؤه.
- لم يتغير منطق اختيار الحسابات أو خرائط الأنشطة أو ترحيل ضريبة القيمة المضافة.

## الاختبارات
- اختبارات SQLite الحالية لدليل الحسابات تظل مرجع السلوك.
- اختبار PostgreSQL اختياري ينشئ مخططًا مؤقتًا وجدول حسابات مستقلًا، ثم يختبر إنشاء الدليل وإضافة الحسابات مرتين مع التحقق من ثبات معرفات الحسابات الموجودة.
- الاختبار يعمل داخل معاملة يتم التراجع عنها؛ لا يستخدم قاعدة بيانات الشركة ولا يترك مخططًا تجريبيًا دائمًا.

## ما لم يصبح متوافقًا بعد
هذه الشريحة لا تعني أن وحدة دليل الحسابات أو النظام كله أصبحا متوافقين بالكامل مع PostgreSQL. يلزم استكمال مراجعة كل عمليات التهيئة والترحيل، ثم اختبار ترحيل VAT ومطابقة الأرصدة وروابط القيود، ومراجعة المعاملات والتزامن على مستوى التطبيق.
