# المرحلة الخامسة: تنفيذ استعلامات كشوف الأطراف عبر طبقة SQL مشتركة

## ما الذي تغير؟
- أضيفت دالة داخل `party_reports.py` باسم `_execute`، وتحوّل تنفيذ الاستعلامات إلى `execute_compat`.
- استبدلت استدعاءات `c.execute` داخل الوحدة البالغ عددها 31 استدعاءً بالدالة المشتركة.
- SQLite يظل ينفذ SQL كما هو، بينما تُحوّل علامات المعاملات الموضعية `?` إلى `%s` عند استخدام psycopg 3.
- لا يوجد في استعلامات هذه الوحدة استخدام لمعامل JSON `?`؛ لذلك لا تصطدم هذه المرحلة بالقيد المعروف في محول المعاملات.

## الاختبارات
- اختبارات NEXUS الحالية على SQLite تظل تغطي كشوف العملاء والموردين والتسويات والأرصدة الافتتاحية والجارية.
- أضيف اختبار تكاملي اختياري يتصل بـ PostgreSQL عبر `NEXUS_TEST_POSTGRES_DSN`، وينشئ مخططًا مؤقتًا وجداول مصغرة ثم ينفذ:
  - أحداث كشف العميل: الفاتورة والمقبوض والإشعار الدائن.
  - أحداث كشف المورد: فاتورة الشراء والإشعار الدائن والسداد.
  - تجميع أحداث العميل والمورد.
  - التحقق من المجاميع العشرية.
- الاختبار يتراجع عن المعاملة ويغلق الاتصال؛ لا ينشئ جداول دائمة ولا يقرأ بيانات الشركة.

## حدود المرحلة — مهمة
- `_db()` ما زالت تفتح SQLite فقط.
- لم يتم تغيير اختيار قاعدة البيانات في Flask أو مسارات التقارير.
- لم يتم نقل كل استعلامات التسوية إلى PostgreSQL بعد؛ هذه المرحلة تثبت تنفيذ استعلامات الأحداث الأساسية فقط.
- لا تزال هناك مراجعة مطلوبة لدوال مطابقة الأستاذ العام، أرصدة أول المدة، المقدمات، والأبعاد التحليلية قبل اعتبار الوحدة متوافقة بالكامل.
- لا تغيير في منطق المحاسبة أو الأرصدة أو صلاحيات العرض.

## قرار التشغيل
هذه خطوة توافق داخلية واختبارية فقط. قاعدة تشغيل التطبيق تبقى SQLite، ولا توجد ترقية أو تحويل أو نسخ بيانات إنتاجية.
