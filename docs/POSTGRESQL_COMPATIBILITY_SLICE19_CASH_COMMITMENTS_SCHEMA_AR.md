# الشريحة 19 — اختبار تهيئة مخطط الالتزامات النقدية على PostgreSQL

## النطاق
- إضافة اختبار تكامل حقيقي لتهيئة جداول الالتزامات النقدية على PostgreSQL.
- تشغيل الاختبار داخل schema مؤقت باسم فريد، وإنشاء جدول `journal_entries` المصغر المطلوب للعلاقات الخارجية.
- التحقق من إنشاء الجداول الأربعة: الالتزامات، الدفعات، الجداول الدورية، واستحقاقات الجداول.
- التحقق من وجود رابط قيد العكس، وإمكانية إعادة تشغيل التهيئة دون تغيير المخطط.
- التحقق من المعرّف المتولد باستخدام `insert_and_get_id` وعبارة `RETURNING id` عبر PostgreSQL.
- حذف الـschema المؤقت الخاص بالاختبار فقط بعد انتهائه.

## الملفات
- `tests/test_cash_commitments.py`

## حدود السلامة
- لا يتم فتح قاعدة بيانات الشركة أو قراءة بياناتها أو تعديلها.
- لا يتم تحويل بيانات SQLite أو تغيير قاعدة التشغيل.
- الاختبار مشروط بوجود `NEXUS_TEST_POSTGRES_DSN`، ويُتخطى عند عدم إعداد بيئة PostgreSQL.
- لا يثبت هذا الاختبار جاهزية دورة الالتزامات بالكامل؛ فهو يغطي تهيئة المخطط وإعادة تشغيلها وتوليد المعرّف فقط.

## بوابة القبول
لا تُغلق الشريحة قبل نجاح اختبار PostgreSQL الفعلي على HEAD النهائي، واختبارات NEXUS وPython checks. تظل SQLite قاعدة التشغيل المعتمدة حتى اكتمال توافق جميع الوحدات واختبارات الترحيل والنسخ الاحتياطي والاستعادة.
