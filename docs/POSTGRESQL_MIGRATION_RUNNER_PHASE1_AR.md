# إطار ترحيلات PostgreSQL — المرحلة الأولى

## ما الذي أُضيف؟
- `postgres_migrations.py` محرك ترحيلات اختياري مستقل عن تشغيل Flask.
- ملفات SQL مرقمة بصيغة `0001_description.sql` داخل مجلد ترحيلات يمرره المستدعي صراحةً.
- ترتيب ثابت حسب رقم الإصدار، وبصمة SHA-256 لكل ملف.
- جدول تتبع `schema_migrations` داخل الـ schema المحدد.
- قفل PostgreSQL استشاري على مستوى المعاملة لمنع تشغيل مهاجرين متزامنين.
- تنفيذ كل الدفعة داخل معاملة واحدة؛ عند فشل أي ملف يحدث rollback للدفعة كلها.
- رفض تعديل ملف سبق تطبيقه إذا تغير الاسم أو checksum.
- `SET LOCAL search_path` يحصر أوامر DDL غير المؤهلة داخل الـ schema المستهدف.

## حدود الأمان الحالية
1. المحرك لا يفتح اتصالًا بنفسه ولا يقرأ `NEXUS_POSTGRES_DSN` ولا يختار قاعدة تلقائيًا.
2. لا يوجد استدعاء من Flask startup، ولا يوجد ترحيل تلقائي عند تشغيل البرنامج.
3. يجب على المستدعي تمرير اتصال PostgreSQL صريحًا بوضع `autocommit=False`، ويجب أن يكون الاتصال idle.
4. يجب تمرير مجلد الترحيلات واسم schema صراحةً.
5. ملفات SQL موثوقة يراجعها المطور فقط؛ لا تستخدم ملفات يرفعها مستخدم أو عميل.
6. اختبارات التكامل تستخدم schema عشوائيًا قابلًا للحذف، ولا تلمس schema الشركة.

## التشغيل في هذه المرحلة
لا توجد أوامر تشغيل إنتاجية ولا ملفات DDL تشغيلية مرفقة بعد. هذه بنية تأسيسية واختبارات؛ لا تستخدمها على قاعدة حقيقية الآن. يظل SQLite قاعدة التشغيل الحالية، ولم يتم نقل أي بيانات.

## الاختبارات المطلوبة
- ترتيب الملفات والتحقق من الأسماء وUTF-8 والملفات الفارغة.
- رفض أسماء schemas غير الآمنة.
- تطبيق مرة واحدة ثم إعادة التشغيل دون تكرار.
- اكتشاف تغيير checksum بعد التطبيق.
- rollback كامل عند فشل migration.
- التحقق أن الجداول تنشأ داخل schema التجريبي لا في public.
- تشغيل اختبارات PostgreSQL فقط عند ضبط `NEXUS_TEST_POSTGRES_DSN` على قاعدة اختبار منفصلة.

## ما لم يُنفذ بعد
- لا توجد ترحيلات فعلية لمخطط NEXUS.
- لا توجد ترحيلات بيانات SQLite إلى PostgreSQL.
- لا يوجد تحويل runtime أو تغيير قاعدة تشغيل التطبيق.
- يلزم لاحقًا مراجعة صلاحيات مستخدم PostgreSQL، سياسة النسخ الاحتياطي، خطة الاستعادة، ونافذة صيانة قبل أي تشغيل على بيئة فعلية.
