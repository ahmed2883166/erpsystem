# طبقة التوافق متعددة قواعد البيانات — أول شريحة

الحالة: تنفيذ أولي معزول، وليس دعمًا تشغيليًا كاملًا لـ PostgreSQL.

## ما أُضيف

- `db_compat.py` يقدم:
  - كشف نوع الاتصال المدعوم (SQLite أو psycopg 3).
  - فحص وجود جدول دون ربط التطبيق بمحرك واحد.
  - قراءة أسماء الأعمدة من SQLite PRAGMA أو PostgreSQL information_schema.
  - التحقق من أسماء الجداول والأعمدة/المخططات قبل إدخالها في SQL؛ القيم العادية تظل معاملات مربوطة.
- `tests/test_db_compat.py` يختبر SQLite محليًا، ويضيف اختبار PostgreSQL تكامليًا مشروطًا بمتغير `NEXUS_TEST_POSTGRES_DSN`. اختبار PostgreSQL ينشئ مخططًا مؤقتًا داخل معاملة ثم يتراجع عنها.

## الحدود المتعمدة

هذه الشريحة لا:
- تستبدل `database.py` ولا تختار قاعدة التشغيل.
- تحول معاملات SQL من `?` إلى `%s`.
- تعالج `lastrowid` أو `executemany` أو `executescript`.
- تنقل الجداول أو البيانات أو تغيّر أنواع المبالغ.
- تجعل وحدات المحاسبة أو المبيعات أو المشتريات أو المخزون متوافقة مع PostgreSQL.

لم نعدّل أي سياسة محاسبية أو مخطط قائم أو بيانات شركات. SQLite تظل قاعدة التشغيل الوحيدة.

## بوابة القبول التالية

1. تشغيل اختبارات هذه الشريحة على SQLite وPostgreSQL 16.
2. إضافة اختبارات تكافؤ لقراءة المخطط على كلا المحركين.
3. بعدها فقط استبدال فحوص المخطط المباشرة في وحدة واحدة مختارة، مع إبقاء استعلامات الوحدة على SQLite إلى أن تُحوّل بالكامل.
4. بناء طبقة تنفيذ معاملات SQL منفصلة ومختبرة؛ لا يجوز إجراء استبدال نصي عام لعلامات `?` أو `INSERT OR IGNORE`.

## حماية البيانات

كل اختبارات PostgreSQL تستخدم مخططًا مؤقتًا ومعاملة متراجَعًا عنها. لا تُستخدم قاعدة الشركة ولا مجلد `data/` في الاختبارات.
