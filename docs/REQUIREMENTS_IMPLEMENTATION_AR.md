# خطة استكمال NEXUS ERP — المتطلبات والاختبارات

هذه الوثيقة تجمع ملاحظات المستخدم المعتمدة للتطوير. التنفيذ على فرع
`feature/company-setup-currency-tax-activity` فقط، ولا يتم الدمج إلى `main`
إلا بعد موافقة المستخدم واختبارات القبول.

## 1. أسعار الموردين ومقارنة الفواتير
- سجل تاريخي لسعر كل صنف لدى كل مورد، مع العملة ووحدة القياس وتاريخ السريان.
- إظهار آخر سعر شراء وسعر أمر الشراء عند إنشاء فاتورة المورد.
- مقارنة سعر الفاتورة بسعر أمر الشراء والسماح بتجاوز السعر فقط بصلاحية محددة مع سبب.
- تقرير تغير الأسعار حسب الصنف والمورد والفترة.

## 2. دورة الاستلام والفوترة (Three-Way Matching)
- متابعة الكمية المطلوبة والمستلمة والمفوترة والمتبقية لكل بند أمر شراء.
- تقرير استلامات غير مفوترة GRNI مع دعم المطابقة الجزئية.
- تقرير فواتير غير مستلمة Invoiced Not Received.
- مقارنة الكميات والأسعار والقيم، ومنع ربط نفس الكمية/القيمة مرتين.
- عرض حالة كل أمر شراء: مفتوح، مستلم جزئيًا، مستلم بالكامل، مفوتر جزئيًا، مكتمل.

## 3. دليل الحسابات حسب النشاط
- الإبقاء على القوالب الحالية للأنشطة: تجاري، صناعي، خدمي، طبي، مطاعم.
- تحسين عرض الشجرة بصريًا وتمييز الحساب التجميعي عن الحساب التفصيلي وإظهار مستويات التبعية.
- مراجعة اكتمال الحسابات الفرعية وقواعد الربط المحاسبي لكل نشاط.
- منع استبدال دليل حسابات مستخدم بعد وجود قيود؛ أي تحويل نشاط لاحق يتطلب إجراء تحويل محاسبي مستقلًا ومراجعًا.

## 4. سجل المراجعة والرقابة (Audit Trail)
- شاشة Admin للبحث حسب المستخدم، نوع العملية، رقم المستند، والفترة.
- تسجيل إنشاء/ترحيل/تعديل/إلغاء المستندات والقيود، مع المستخدم والتاريخ والوقت.
- حفظ القيم قبل وبعد التعديل وسبب الإلغاء/التعديل.
- عدم السماح بحذف سجل التدقيق أو تغييره من واجهة التطبيق.
- القيود المرحلة لا تحذف؛ التصحيح يكون بقيد عكسي مرتبط بالأصل.

## 5. السنوات والفترات المالية
- تعريف سنة مالية بتاريخ بداية ونهاية قابلين للإعداد.
- حالة السنة والفترات: مفتوحة، مغلقة.
- منع الترحيل والتعديل والحذف في الفترات المغلقة لكل الوحدات، وليس شاشة القيود فقط.
- صلاحية إعادة الفتح للـ Admin فقط، مع سبب وتسجيل كامل في Audit Trail.
- تقرير جاهزية الإقفال يوضح القيود غير المتوازنة والمستندات غير المرحلة وفروق المطابقة والحركات المعلقة.

## 6. الإقفال السنوي والافتتاحيات
- إقفال حسابات الإيرادات والمصروفات في حساب الأرباح المحتجزة/الحساب المعتمد.
- ترحيل أرصدة حسابات الميزانية إلى أول يوم في السنة التالية.
- إنشاء قيد افتتاحي متوازن مع مرجع واضح وربطه بسنة المصدر.
- ترحيل الأرصدة التفصيلية للعملاء والموردين والبنوك والصندوق والمخزون حسب الصنف والمخزن، وليس الاكتفاء بإجمالي الأستاذ العام.
- منع التكرار وإتاحة معاينة القيود والأرصدة قبل اعتماد الإقفال.
- الاحتفاظ بتقارير ودفاتر السنة السابقة كما كانت وقت الإقفال.

## 7. عناصر سابقة ضمن نفس حزمة الملاحظات
- استكمال سجل الأصول الثابتة وجدول الإهلاك ومراجعة حدود القيمة القابلة للإهلاك.
- تقرير أعمار ديون العملاء والموردين حسب تاريخ الاستحقاق والتوزيعات الفعلية.
- عروض الأسعار وقوائم الأسعار الخاصة بالعملاء وتحويل العرض المقبول إلى فاتورة دون إعادة إدخال.
- تصدير التقارير إلى PDF/Excel حيثما يكون مناسبًا، مع وضوح الحسابات الرئيسية والفرعية.

## ضوابط التنفيذ والقبول
- ترحيلات قاعدة البيانات يجب أن تكون آمنة ومتوافقة مع قواعد البيانات الحالية، مع نسخة احتياطية قبل أي ترحيل بنيوي.
- لا تُعدّل بيانات الشركة أو الأرصدة الموجودة تلقائيًا أثناء التحديث.
- كل ميزة لها اختبارات منطقية واختبارات تكامل على قاعدة بيانات اختبارية.
- لا توصف الميزة بأنها مكتملة قبل نجاح الاختبارات ومراجعة مسارات الواجهة.
- التصنيع وBOM وأوامر الإنتاج تظل خارج النطاق في هذه المرحلة وفق القرار السابق.
