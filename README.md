# NEXUS ERP v0.1

نواة نظام محاسبي وإداري باللغة العربية للأنشطة التجارية والخدمية. العملة الافتراضية هي الريال السعودي (SAR)، ويمكن تشغيله على جهاز واحد أو مشاركته داخل الشبكة المحلية LAN.

## ما يتضمنه الإصدار الأول

- واجهة عربية من اليمين إلى اليسار ولوحة مؤشرات مالية مبسطة.
- دليل حسابات، قيود يومية متوازنة، ميزان مراجعة ودفتر أستاذ عام.
- أدوار: مدير النظام، محاسب، ومشاهد، مع صلاحيات دقيقة بحسب الوظيفة.
- إنشاء مستخدمين وسجل تدقيق للعمليات الأساسية.
- نسخة احتياطية واستعادة آمنة لقاعدة البيانات.
- استيراد دليل الحسابات من CSV وتصديره بصيغتي CSV وJSON.
- بنية قابلة للتوسعة لاستيراد/تصدير Excel وXML وPDF، والقوائم المالية والتحليلات المتقدمة.

## التشغيل على Windows

1. ثبّت Python 3.11 أو أحدث.
2. من داخل مجلد المشروع شغّل:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

3. افتح `http://localhost:5000`.

بيانات الدخول الأولية: `admin` / `admin123`. يجب تغيير كلمة المرور وتعيين مفتاح سري قوي عبر متغير البيئة `NEXUS_SECRET_KEY` قبل أي استخدام فعلي.

## التشغيل على LAN

الخادم يستمع افتراضيًا على `0.0.0.0:5000`. بعد السماح بالمنفذ 5000 في جدار حماية Windows، تفتح الأجهزة الأخرى `http://IP-ADDRESS:5000`. للاستخدام الإنتاجي شغّل التطبيق خلف خادم WSGI آمن، وفَعّل HTTPS، وانقل قاعدة البيانات إلى خادم مركزي مُدار.

## ملاحظات النطاق

هذه نسخة بداية تشغيلية للمحاسبة العامة. القوائم المالية الكاملة (قائمة الدخل، المركز المالي، التغيرات في حقوق الملكية، والتدفقات النقدية)، تقارير Excel/XML/PDF، وعمليات المبيعات والخدمات التفصيلية هي مراحل تالية موثقة في خطة المشروع.


## وحدة المخزون — أساس التنفيذ الأول

أضيفت على فرع التطوير شاشات تعريف الأصناف والمخازن وحركات الاستلام والصرف والتحويل والتالف/الإعدام، مع تتبع التشغيلة/الصلاحية للأصناف المفعّل لها ذلك، وطبقات تقييم FIFO أو المتوسط المرجح، ومنع الصرف الذي يتجاوز طبقات الرصيد المتاحة.

لتشغيل التطبيق كما هو موضح أعلاه، افتح القائمة الجانبية المخزون بعد تسجيل الدخول. أضف الأصناف والمخازن أولًا، ثم سجّل الاستلام قبل الصرف. اختيار طريقة التقييم موجود في إعداد الشركة.

**مهم — حالة هذا التسليم:** هذه دفعة تأسيسية قيد المراجعة وليست إصدارًا إنتاجيًا. لم يُنفذ بعد الربط الآلي الكامل مع القيود المحاسبية، الجرد المعتمد، موافقات المستندات، قوائم أسعار متقدمة، أو تصدير Excel/PDF. لم يتم تشغيل اختبارات على جهاز المستخدم ضمن هذا التغيير. لا تعتمد بيانات فعلية قبل إكمال الاختبارات والمراجعة المحاسبية والأمنية. أوامر الإنتاج والوصفات وتحويل الخامات إلى منتج تام خارج النطاق عمدًا.


## دورة المشتريات — Purchasing v1 (قيد التطوير)

أضيفت وحدة مشتريات على فرع التطوير تشمل:
- دليل الموردين وأوامر الشراء.
- إذن استلام مشتريات يحدّث حركة المخزون وطبقات التقييم.
- قيد GRNI تلقائي: مدين المخزون / دائن بضاعة مستلمة غير مفوترة.
- فاتورة المورد وتسوية GRNI دون إثبات المخزون مرة ثانية.
- ضريبة المدخلات لا تُرحّل إلا عند وجود حساب ضريبي تفصيلي صالح.
- سداد المورد وتوزيع الدفعة على أقدم الفواتير المفتوحة.

شاشة أوامر الشراء موجودة، لكن ربط سطور أمر الشراء بكميات الاستلام الجزئي ما زال مطلوبًا. الفاتورة المباشرة دون إيصال استلام تسجل قيمة المخزون محاسبيًا ولا تنشئ كمية مخزنية؛ لذلك استخدم إيصال الاستلام لتحديث الكميات. يلزم استكمال اختبارات التكامل، المرتجعات والإشعارات الدائنة والدفعات المقدمة واعتمادات المستندات قبل الاعتماد الفعلي.

آخر CI لهذه الدفعة: compile check واختبارات الوحدة نجحت على GitHub Actions. هذا لا يعني اكتمال اختبار واجهة المستخدم أو القبول التشغيلي.
